# 📛 命名规则

## 1. 文件命名

### 1.1 Skill文件
- 采用小写字母和连字符组合
- 使用描述性的名称
- 示例: `neoforge-1.21.1-api.md`

### 1.2 目录命名
- 采用小写字母和连字符组合
- 使用技术栈或主题名称
- 示例: `minecraft-modding`, `web-development`

### 1.3 版本标识
- 使用语义化版本号
- 格式: `major.minor.patch`
- 示例: `1.21.1`, `20.1.0`

## 2. Skill命名

### 2.1 命名格式
- 必须包含技术栈名称
- 必须包含版本号(如有)
- 可以包含功能描述

### 2.2 示例
- `neoforge-1.21.1-dimension-api`
- `fabric-1.21.1-item-modification`
- `web-frontend-react-components`

## 3. 标签命名

### 3.1 分类标签
- 使用简洁的分类名称
- 示例: `minecraft`, `api`, `guide`, `reference`

### 3.2 版本标签
- 使用版本号作为标签
- 示例: `1.21.x`, `1.20.x`

## 4. 命名原则

- 唯一性: 避免名称冲突
- 一致性: 保持命名风格统一
- 可搜索性: 使用易于搜索的关键词
- 可扩展性: 预留未来扩展空间
